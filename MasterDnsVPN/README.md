# MasterDnsVPN (DNS-туннель нового поколения)

**MasterDnsVPN** — это высокоскоростное, сверхнадежное решение для построения VPN-туннелей поверх протокола DNS. Оно разработано для обхода самых жестких блокировок интернета (когда заблокирован весь TCP и UDP трафик, но серверы имен DNS продолжают обрабатывать запросы).

Проект написан на высокопроизводительном языке Go и включает развитые механизмы оптимизации, сжатия трафика, ARQ (автоматический запрос повторной передачи для надежности) и шифрования данных.

---

## 🛠️ Архитектура системы

Система состоит из двух основных компонентов:

1. **MasterDnsVPN Client (`cmd/client`)**: 
   * Запускается на стороне пользователя (Android, Linux, Windows, macOS).
   * Перехватывает сетевой трафик и инкапсулирует его в зашифрованные DNS-запросы к субдоменам вашего базового домена.
2. **MasterDnsVPN Server (`cmd/server`)**:
   * Запускается на сервере с белым IP-адресом, делегированным для обработки DNS-запросов (порт 53 UDP).
   * Принимает зашифрованные DNS-запросы от клиентов, собирает пакеты, расшифровывает их и перенаправляет в локальный или внешний SOCKS5-прокси (например, Xray/Vless) для выхода в интернет.
   * Интегрирован с SQLite-базой данных панели **3x-ui** для проверки активности учетных записей, UUID-ключей и лимитов трафика клиентов.

## 📦 Автоматическая сборка и CI/CD (GitHub Actions)

В проекте настроен передовой пайплайн сборки на базе GitHub Actions (**`.github/workflows/build-go.yml`**):

* **Мультиплатформенная кросс-компиляция**: Автоматическая сборка бинарных файлов клиента и сервера под следующие операционные системы и архитектуры:
  * **Windows** (amd64, x86, arm64) с генерацией ресурсов и иконок.
  * **Linux** (amd64, arm64, x86, armv7, armv6, armv5, riscv64, mips, mipsle, mips64, mips64le).
  * **macOS** (amd64, arm64).
  * **Android / Termux** (arm64, armv7 с CGO-компиляцией через Android NDK).
* **Smoke Testing (Дымовое тестирование)**: Автоматический запуск собранных бинарников в изолированном окружении GitHub Runners для проверки стабильности инициализации перед выпуском.
* **Автоматические релизы**: При запуске workflow автоматически формируются ZIP/TAR архивы с бинарными файлами, конфигурационными файлами-примерами и HTML-документацией. Генерируется детальный Release Notes на основе коммитов и PR.
* **Docker Image публикации**: Автоматическая сборка многоархитектурных Docker-образов и отправка их в GitHub Container Registry (GHCR).

### Запуск CI/CD сборки
1. Перейдите во вкладку **Actions** вашего GitHub-репозитория.
2. Выберите рабочий процесс **Build and Release (Go)**.
3. Нажмите кнопку **Run workflow** справа.
4. После успешного завершения все бинарники будут прикреплены к релизу на GitHub.

## 🔧 Быстрая настройка сервера

1. **Настройка DNS-записей у регистратора домена:**
   Создайте NS-запись, указывающую на ваш сервер:
   ```
   vpn.example.com.      IN NS  ns.example.com.
   ns.example.com.       IN A   1.2.3.4 (IP вашего сервера)
   ```
2. **Конфигурация сервера (`server_config.toml`):**
   ```toml
   PROTOCOL_TYPE = "udp"
   UDP_HOST = "0.0.0.0"
   UDP_PORT = 53
   DOMAIN = ["vpn.example.com"]
   
   # Интеграция с базой данных 3x-ui для авторизации клиентов
   SQLITE_PATH = "/etc/x-ui/3x-ui.db"
   
   # Перенаправление трафика в SOCKS5-прокси панели 3x-ui
   USE_EXTERNAL_SOCKS5 = true
   FORWARD_IP = "127.0.0.1"
   FORWARD_PORT = 10808
   ```
3. **Запуск сервера:**
   ```bash
   ./MasterDnsVPN_Server_Linux_AMD64 --config server_config.toml
   ```

## 🔒 Безопасность и шифрование

Все данные между клиентом и сервером шифруются с использованием симметричного ключа (`clientKey`), который автоматически генерируется как UUID клиента в панели 3x-ui. Никто из промежуточных DNS-провайдеров или систем DPI не сможет расшифровать содержимое проходящего туннелированного трафика.
